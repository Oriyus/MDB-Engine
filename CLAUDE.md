# MDB Engine

A from-scratch 3D game engine and editor for Windows. C++20, OpenGL 4.5 (core, DSA style), built with CMake.
The engine is a static library (`Engine`). Two apps use it: `MDBEditor` (the editor, in `Editor/`) and `Game` (the standalone player, no editor).

## Build

Visual Studio 2026 generator. Dependencies download through CMake FetchContent.

```powershell
cmake -S . -B build -G "Visual Studio 18 2026" -Wno-dev
cmake --build build --config Debug
.\build\bin\Debug\MDBEditor.exe [--project <folder>]               # the editor (the last project, else Examples)
.\build\bin\Debug\Game.exe [--project <folder>] [--scene x.json]   # the game (settings in <project>/project.json; default Examples)
cmake --build build --config Release --target package_game   # build/dist/Release: the Examples game (or -DGAME_PROJECT=<folder>), ready to zip
cmake --build build --config Release --target package_editor # build/dist/MDB Engine: the editor to share (no build needed to run it)
```

- **Packaged editor** (`package_editor`, root `CMakeLists.txt`; README from `Editor/package/README.txt`): `MDBEditor.exe`, `Player/Game.exe`, `EngineAssets`, `Examples` (Assets + project.json), `Docs`. `Projects::Packaged()` is true when `EngineAssets/Shaders` is next to the exe (`Platform::ExeDir`); then `EngineDir()` / `ExamplesDir()` and `MDB_PROJECT=Examples` use the exe's folder instead of the compiled-in source paths, and `GameBuilder` copies `Player/Game.exe` instead of running CMake.

Game.exe also takes `--fullscreen`, `--windowed`, `--width N`, `--height N`, `--no-vsync` (uncapped, for timing) and `--quit-after <seconds>` (a test hook) and `--save-dir <folder>` (save slots; default `%APPDATA%/<title>/Saves`). Release builds of Game have no console window. Its keys: Esc pauses (a menu with Resume / Restart / Quit buttons; R and Q work too), and F11 or Alt+Enter toggles full screen.

- After adding or deleting a source file, re-run the configure line first. `Engine/CMakeLists.txt` collects sources with `file(GLOB_RECURSE ...)`. `Editor/CMakeLists.txt` lists its sources by hand, so add new editor files there.
- Edits to existing files only need the build line.
- Shaders are read from disk at runtime. **F5** in the app reloads them, so no rebuild is needed.
- **Projects.** A game is a project: a folder with `project.json` (title, start scene, window size, fullscreen, vsync, `exclude` patterns; `Core/Project.h`) and `Assets/`. The engine's own files are apart in `EngineAssets/` (Shaders, `Scripts/Lib`, the built-in sample model `Models/BoomBox.glb`). The engine repo's `Examples/` is a project holding every example level and test script. Engine classes take both folders as constructor arguments (`SceneRenderer(engineDir, assetDir)`, `ResourceLibrary(assetDir, engineDir)`, `GameSession(scene, assetDir, engineDir, ...)`, which passes them to `ScriptEngine`) and never read compile definitions. Script libraries load from `EngineAssets/Scripts/Lib` first, then the project's `Assets/Scripts/Lib`. The editor (`Editor/src/Projects`) opens `--project`, else `MDB_PROJECT`, else the most recent project (`%APPDATA%/MDB Engine/projects.json`), else Examples (`EXAMPLES_DIR`). It works on one project per run: File > Open Project / Recent Projects / New Project restart it with `--project` (`Platform::LaunchSelf` in `OnShutdown`, after the unsaved-changes questions). Without test hooks it opens the project's start scene; Example Levels shows only in the Examples project. The Game uses `--project`, else `project.json` next to its exe (a packaged game, with `EngineAssets` beside it), else Examples; engine files come from `EngineAssets` next to the exe, else `ENGINE_ASSET_DIR`. **File > Build Game** (`Editor/src/GameBuilder`, a background thread) runs `cmake --build <build dir> --config Release --target Game` (`MDB_CMAKE_COMMAND`, `MDB_BUILD_DIR`) and fills `<output>/<title>/` with `<title>.exe`, `EngineAssets`, the project's `Assets` minus `exclude` and `project.json` (default output `<project>/Build`, which New Project's `.gitignore` ignores; an existing folder is replaced only if it holds a `project.json`). The first build compiles the engine in Release (about 2.5 minutes).
- Unattended test runs: **set `MDB_PROJECT=Examples`** (or a project folder; the editor otherwise opens the last project used, and env-chosen projects are not added to the recent list). The environment variables `MDB_WINDOWED=1` (a plain 1600 x 900 window instead of maximized, for screen captures), `MDB_DEMO=script`, `coinrush`, `tactics`, `cellar` or `terrain` (build that example level), `MDB_TERRAIN_TOOL=raise|smooth|flatten|noise|paint[:1-4]|scatter[:a.gltf,b.gltf]` (pick that terrain brush; with `MDB_SELECT=Terrain`; scatter also sets the items), `MDB_SCATTER_FILL=1` (Scatter > Fill terrain on the selected terrain once; `MDB_AUTOPLAY` then presses Play after it)|smooth|flatten|noise|paint[:1-4]` (pick that terrain brush; with `MDB_SELECT=Terrain`), `MDB_AUTOPLAY=1` (press Play), `MDB_TEST_SCRIPT=Scripts/x.lua` (add a "Test" entity running it), `MDB_SCENE=<file>` / `MDB_SAVE_SCENE=<file>` (load first / save last, in the project's `Assets/Scenes`), `MDB_SAVE_DIR=<folder>` (save slots while play-testing; default `%APPDATA%/MDB Engine/Editor Saves/<project title>`), `MDB_BUILD_GAME=<folder>` (File > Build Game into it; the editor waits for the build when it quits), `MDB_OPEN_DIALOGUE=Dialogues/x.json[#node]` (open the Dialogue Editor on it) with `MDB_SAVE_DIALOGUE=1` (re-save it through the editor), `MDB_OPEN_ANIMGRAPH=AnimGraphs/x.json` (open the AnimGraph Editor on it), `MDB_OPEN_DATABASE=1|npc:<id>|item:<id>` (open the Database window, on that entry; `MDB_SAVE_DATABASE=1` re-saves it), `MDB_OPEN_UI=UI/x.json[#widget]` (open the UI Editor on it; `MDB_SAVE_UI=1` re-saves it) and `MDB_QUIT_AFTER=<seconds>`, `MDB_MOTION_VECTORS=1` (Viewport > Debug > Motion Vectors on), `MDB_PREVIEW_ASSET=Models/x.glb` (show that model in the Inspector's preview), `MDB_VIEW_MODE` / `MDB_SELECT` (see Viewport shading), `MDB_NO_VSYNC=1` (an uncapped frame rate, for timing: a capped one hides the real cost) and `MDB_PROFILE=1` (every 300 frames the log gets the average ms per frame of each `PROFILE_SCOPE`, nested; `Core/Profiler.h`; off it costs one branch per scope; plus `gpu:` lines with the **GPU time of each render stage**, from GL timestamp queries read three frames later, `Renderer/GpuTimer` marks in `SceneRenderer::Render`. The CPU scopes only show submission, and a GPU-bound frame shows up as CPU time waiting in whichever call blocks, often "Shadow passes"). The Game takes the same variables: `MDB_PROFILE=1 Game.exe --project Examples --scene village.json --no-vsync` is the way to profile a shipped level. Redirect stdout to read the log. Time things in the **Release** editor: Debug is many times slower on per-object CPU work (the village forest: 40 ms Debug, 2.5 ms Release).

## Pitfalls (these cost time before)

- **Debug builds use `/Ob1`** (inline only what is declared inline) for `Engine`, `MDBEditor`, `Game`, `Jolt` and `imgui` (root `CMakeLists.txt`, after the targets exist; it overrides the `/Ob0` of the Debug flags, hence MSVC warning D9025). Unoptimised and debuggable, but glm/EnTT/STL calls inline. **Don't apply it globally**: with every library at `/Ob1` the editor hit a Debug-heap assertion (`_CrtIsValidHeapPointer`) while assimp loaded the first model. Load-time libraries keep their defaults. Debug frame on the village forest went 39.7 -> 10.1 ms (Play) with this and the fixes below; Release 2.4 ms.
- **Per-object work every frame is what a Debug build pays for.** Profile with `MDB_PROFILE=1 MDB_NO_VSYNC=1`. Fixed so far: the Hierarchy draws only visible rows (`ImGuiListClipper` over a flattened tree; open state in `m_HierarchyExpanded`, nodes start folded and a new selection unfolds its parents); `TransformComponent::GetMatrix` builds TRS directly (no 4x4 multiplies; same numbers); `BuildDrawList` skips an identity `LocalOffset` multiply and works out each object's world box once for all views (`Frustum::WorldBox`); `DrawList::AddBatches` stable-sorts indices with a field-by-field `DrawBatch::operator<` (not 80-byte items through `std::tie`); `PhysicsWorld::Step` re-checks the world pose of static bodies only if they have a parent; the foliage obstacle list is rebuilt only when a hash of the raw transforms changes; the collider overlay projects each box's 8 corners once, skips boxes off screen and draws unselected outlines 1 px wide.

- **Never create files through Visual Studio's Solution Explorer.** It appends quoted file names to the first `add_library(...)` in `Engine/CMakeLists.txt`, which compiles engine files into the wrong target (errors like "Cannot open include file" inside `imgui.vcxproj`). Create files in File Explorer or the editor, then re-run configure. If the error appears, remove the stray quoted names from `Engine/CMakeLists.txt`.
- `imgui.h` must be included **before** `ImGuizmo.h`.
- ImGui is the **docking** branch (`v1.91.0-docking`). ImGuizmo is vendored by hand in `vendor/imguizmo/` (two files). It is not fetched.
- glad and stb are vendored in `vendor/glad` (own CMakeLists) and `vendor/stb` (`stb_image.h`, implementation defined in `Texture.cpp`).
- Every sampler uniform needs its own texture unit, even when unused. Two sampler types on one unit is a GL error.
- The editor layout is saved in `editor.ini` next to the exe (git-ignored). Window > Reset Layout rebuilds it; deleting the file does too.
- `*.obj` is git-ignored for compiled objects; `!/Examples/Assets/**/*.obj` and `!/EngineAssets/**/*.obj` keep model files (your own project needs the same exception if it has .obj models and ignores *.obj).
- ImGuizmo's Scale gizmo is always local space. That is by design, not a bug.
- `ScriptEngine.cpp` (sol2) needs `/bigobj`, set per file in `Engine/CMakeLists.txt`. Lua 5.4 has no CMake, so it is built there as the `lua` target.
- In sol2, `table.get_or<T>(key, def)` is ambiguous when `def` is already a `T` rvalue. Use `get<sol::optional<T>>(key).value_or(def)`.
- miniaudio is fetched with `SOURCE_SUBDIR header-only` (a folder that does not exist), so its own CMake project is not built. Only `miniaudio.h` is used.
- GLFW key state is polled once per frame. Simulated key taps (down and up in one go, like WScript `SendKeys`) are never seen, so hold the key across frames.
- A forward declaration must use the same keyword as the definition (`struct ShadowContext`, not `class`). MSVC puts the keyword in the mangled name, so a mismatch gives LNK2019 depending on include order.
- Windows PowerShell 5.1 `Set-Content -Encoding utf8` writes a BOM. Edit source files with the Edit tool or sed instead.
- **Don't use `glm::eulerAngles`** to turn a rotation back into `TransformComponent::Rotation`: next to gimbal lock (the middle angle near +-90 degrees, e.g. a camera heading of exactly 90) float rounding makes it wrong by degrees, differently every frame (the tactics camera shook while settling). Use `Scene::EulerFromQuat`, which always rebuilds the same rotation. `Scripts/transform_test.lua` checks it.
- **Shell dialogs (the folder picker) hang on the main thread**: miniaudio initialises COM there as multithreaded (WASAPI), and `IFileOpenDialog` needs a single-threaded apartment. `Platform::PickFolder` runs it on its own STA thread and keeps dispatching the main thread's messages while waiting (the dialog's owner is the editor window, so a plain `join()` deadlocks too). `MDB_TEST_PICK_FOLDER=1` opens it at start to check.

## Architecture

- **Application** runs the loop and calls the virtual hooks `OnStart`, `OnUpdate(dt)`, `OnImGui`, `OnShutdown`. Each app defines `Engine::CreateApplication()`. `Application(WindowProps)` sets the title, size, vsync and fullscreen (`Window::SetFullscreen` toggles at runtime). `Application::GetCommandLineArgs()` holds argv.
- **Shared runtime, used by both apps.** `SceneRenderer` renders a scene through a camera to a texture: the editor shows it in the Viewport, the game draws it full window with ImGui's background draw list. It also owns environment requests (baked at the next Render) and Apply/GatherSettings for the render part of `SceneSettings`. `GameSession` owns PhysicsWorld, AudioEngine, PrefabLibrary and ScriptEngine. It provides Start/Stop/Update (in the right order), restart requests, the game camera and the listener. Snapshots on Play/Stop and restart are the app's job (`Scene::Capture`/`Restore`). `ResourceLibrary` provides the named resources and must outlive the session.
- **ECS (EnTT).** `Entity` is a thin handle (`Add<T>`, `Get<T>`, `Has<T>`, `Remove<T>`). Every entity gets `TagComponent` and `TransformComponent`.
  Components: `MeshRenderer`, `PointLight`, `DirectionalLight`, `Spin`, `Orbit`, `RigidBody`, `Script`, `Camera`, `AudioSource`, `Animator`, `ParticleEmitter`, `Foliage`, `GrassBlocker`, `Terrain`, `Npc`, `Pickup`, `Prefab`, plus `ID` and `Parent` for the hierarchy.
  Transforms store position, Euler rotation in radians, and scale, **relative to the parent** (see Hierarchy).
- **Scene** holds the systems. `OnUpdate` runs Spin and Orbit. `RenderShadows` and `Render` draw the scene.
- Components also include `Collider` (an extra shape for the nearest ancestor body).
- **Adding a component type means updating these places:** `Components.h`; `EntitySnapshot` plus `CaptureEntity`/`CreateFromSnapshot` in `Scene` (used by play mode, `DuplicateEntity`, script clone and scene Load); and `ComponentsToJson`, `ComponentsFromJson` and `ClearComponents` in `Scene/EntityJson.cpp`. Scene files and prefab files both go through those functions. Also add an Inspector section in `Editor/src/main.cpp`.
- **Hierarchy.** Every entity has an `IDComponent` (a random 64-bit ID, kept by snapshots, undo and scene files). A child has a `ParentComponent{ parent ID }`, never an entt handle, because those change when a scene is restored. `Scene` provides `GetParent`, `GetChildren`, `SetParent(child, parent, keepWorld)` (refuses loops), `GetWorldMatrix`, `SetWorldMatrix/Position/Rotation` and `Decompose`. `FindByID` uses a map that EnTT signals mark dirty. Everything spatial works in world space: rendering, lights, physics, audio, game cameras, the gizmo, collider and frustum overlays, script `forward` / `look_at` / `world_position`. `DestroyEntity` takes the children too, and `DuplicateEntity` copies the subtree with new IDs. Physics: static and kinematic bodies follow their parent. Dynamic bodies are simulated in world space and written back as local, so they ignore the parent's motion. Scene files store `id` and `parent` next to name and transform. Older files without IDs get new ones.
- **Scripting.** `ScriptComponent{ Path }` points at a Lua file in `Assets/Scripts`. Scripts run only during Play. Each entity gets its own Lua environment, and the `shared` table is common to all scripts. Each frame runs `Scene::OnUpdate`, then `ScriptEngine::Update` (`on_update`), then `PhysicsWorld::Step`, then `ScriptEngine::DispatchCollisions` (`on_collision_begin/end`, `on_trigger_enter/exit`). On Play, `PhysicsWorld::Sync` runs before `ScriptEngine::Start`, so `on_create` can already use `self.body`. Script destroys and script swaps are deferred until nothing is iterating. A script that errors is disabled and its error is shown in the Console panel. **Script UI** is immediate mode. `ui.text`, `ui.rect`, `ui.bar`, `ui.image` (from `Assets/Textures`, via `UITextureCache`) and `ui.button` (returns true on the frame it is clicked) add `ScriptUIItem`s for this frame, drawn in call order by `DrawScriptUI` (`Runtime/GameUI`). Positions are 0..1 of the view, and sizes are given at 720p. Each frame the app calls `ScriptEngine::SetPointer` (mouse over the view, 0..1, and button state) before Update. The editor does this only while looking through the game camera, so other clicks stay the editor's. `ui.mouse()` reads it. **Laid-out UI** (`Runtime/UILayout`, `UIContext`, owned by the script engine): `ui.begin_panel` / `begin_row` / `begin_column` / `begin_scroll` ... `end_*` place `label` (word wrap, markup `{#rrggbb}..{/}`, `{b}..{/b}`), `button` (clicks on release), `image`, `bar`, `slot` (drag and drop: `drag = value` on the source, the target gets it back as `dropped`), `tabs`, `separator`, `space` and `tooltip`s (after 0.35 s). Layout works in units (pixels at 720p, so it scales) and writes the same `ScriptUIItem`s (new kinds: `Border`, `ClipPush` / `ClipPop`, 9-slice `Image` via `Slice`, `Regular` font, `Shadow`), so the old positional `ui.text/rect/bar/image/button` calls still work beside it (positional buttons register as blockers). Auto sizes (panel `h` or `w` = 0) use last frame's measurement, and hover goes only to the topmost panel under the pointer as of last frame. `ui.wants_mouse()` tells world clicks from UI clicks. Text is measured with the game fonts (`UIFonts`: Segoe UI Bold + Regular, `ScriptEngine::SetUIFonts`; the atlas is built on first use if no ImGui frame has run yet). `SetPointer` also takes the wheel and the right button. `ui.simulate_pointer` drives it in tests (`Scripts/ui_test.lua`, 19 checks: `MDB_SCENE=tactics_test.json MDB_AUTOPLAY=1 MDB_TEST_SCRIPT=Scripts/ui_test.lua`). `scene.quit()` closes the game (in the editor, it stops Play). `scene.restart()` asks the session to enter the current level again, as it was entered, on the next frame (`GameSession::RequestRestart`, carried out by `ApplyPending`).
- **Audio.** `AudioEngine` plays one-shots (`Play`, `PlayAt`) and keeps one voice per `AudioSourceComponent` in step with its entity in `Update`, which runs each simulated frame. The listener follows the camera being drawn. Pause pauses the audio device, and Stop calls `StopAll`. Decoded clips are cached per file, and a clip that fails to load warns once. Without a device, everything does nothing. Scripts use `audio.play` / `audio.play_at`, `e.audio` and `e:add_audio`.
- **Combat support (engine pieces).** `scene.world_to_screen(pos)` is the exact inverse of `screen_ray` (same primary camera and `SetViewAspect`): x, y (0..1), visible, depth. **Decals** (`Scene/Decal.h`, `Renderer/DecalRenderer`, `Shaders/decal.*`): scripts fill `Scene::Decals` each frame with `decal.draw` (cleared at the start of `ScriptEngine::Update`, kept while paused, cleared on Stop and `Scene::Clear`). After the sky and before see-through surfaces, `SceneRenderer` copies the HDR depth (`glCopyImageSubData` into a DEPTH24_STENCIL8 texture: sampling the attached one would be a feedback loop) and draws each decal as a box from `gl_VertexID` (front faces culled, so the camera can be inside; depth test off; entity-ID target masked), one instanced draw per texture with the data in a storage buffer at **binding 3**. The fragment shader rebuilds the world position from depth, keeps what is inside the box, and fades on steep surfaces (normal from `dFdx/dFdy`, taken before any discard) and towards the box's top and bottom. Shapes: circle (ring = an outline), square, texture; thickness, fill, softness, emission. **Line of sight and cover** (`NavGrid::LineOfSight / CoverAt / VisibleCells`, static bodies only): sight is a ray between eye and chest heights; cover probes three rays across the body (agent radius apart, 2 of 3 must hit) about a cell towards the attacker at `CoverLow` 0.6 m and `CoverHigh` 1.5 m: half or full. **Primitives** `capsule` (1 x 2), `cylinder` (1 x 1), `cone` (1 wide base, 1 tall) come from `Mesh::CreateCapsule/Cylinder/Cone` (a lathe of a profile, same winding as the sphere) via `ResourceLibrary`. **Hit flash**: `MeshRendererComponent::FlashColor/FlashTime/FlashDuration` (runtime, not saved) add to the emissive colour while `Scene::OnUpdate` fades them; `e:flash()` sets the whole subtree. The tactics enemies are placeholder figures (capsule body, head, glowing eyes, cone hat) as children of `Enemy`; `MarkStatic` skips `Enemy` and `Hero` (tactics.lua moves them; a merged part would stay behind). `Scripts/engine_features_test.lua` checks all of it (22 checks).
- **Fog of war** (`Navigation/FogOfWar`, owned by `GameSession`, Lua `fog.*`; `Scene::Fog` is the `FogOfWarState` the renderer draws, `Scene/Fog.h`). One value per nav grid column (2D: a column is seen if any of its floors is). `fog.enable` sizes the map to the grid (baking it if needed). Each frame `ScriptEngine::Update` clears what is visible (`BeginFrame`), scripts call `fog.reveal(pos, radius)` for each viewer, and after events `EndFrame` marks visible columns explored, fades the shown values (`FadeSpeed`) and bumps `Revision`. Reveal is line of sight from eye height to **chest height** (1.0 m, so `is_visible` agrees with whether a unit there could be seen), with floorless columns (walls, crate sides) shown next to a seen floor; results are cached per viewer position (0.5 m steps) and dropped when the grid is rebaked (`NavGrid::BakeCount`). Measured: about 2.5 ms per new viewer position in Debug (radius 9). `SceneRenderer` draws it after particles with `fog.frag` (fullscreen, the shared depth copy, RG8 map with linear filtering for soft edges, border = unexplored, sky untouched, entity IDs kept so clicks still pick); the map is uploaded only when `Revision` changes. `SceneRenderer::ShowFog` (Viewport > View > Fog of War) hides it while play-testing. Hiding units: `MeshRendererComponent::Hidden` (runtime; Lua `e.visible`, the whole subtree) skips the part in `BuildDrawList`, so it casts no shadow either. Saving is the game's job: `fog.save()` / `fog.load()` (tactics.lua does it in `on_save` / `on_load`, so levels keep their explored map). Cleared on Start/Stop. `Scripts/fog_test.lua` checks it (17 checks).
- **Dialogue and events.** `events.emit(name, data)` queues an event that every script with `on_event(self, name, data)` gets after the frame's `on_update` (`ScriptEngine::DispatchEvents`, up to 8 rounds of events emitting events). `data.load(path)` reads any JSON under Assets into a Lua table. `Scripts/Lib/*.lua` run once in the shared globals at Start (`LoadLibraries`), before any `on_create`. `Lib/dialogue.lua` is the runner: `dialogue.open(name, { speaker })` reads `Dialogues/<name>.json` (every time, so edits saved during Play are used next time), and `talk:update()` draws the default box (laid-out UI, number keys, Space) until it returns false; custom presenters use `talk.text/speaker/options`, `choose`, `continue`, `close`. Nodes: **line** (speaker, text, on-show action/event, choices or `next`), **branch** (`cond` -> next / else), **action** (action, event, next); `next = 0` ends. Conditions are Lua expressions and actions Lua statements, compiled once per conversation in an env with the globals, `speaker` and `dialogue.helpers` (inventory.lua adds give / take / has_item); a broken one is logged with the dialogue name and node, and counts as false / is skipped. - **Navigation** (`Navigation/NavGrid`, owned by `GameSession`, Lua `nav.*`). One grid serves both free movement (exploring) and grid movement (turn-based combat). The bake casts a ray down every column (cell size in X/Z, aligned to whole multiples of it) against **static** bodies only (`PhysicsWorld::RaycastAll`, `staticOnly`) and keeps every upward surface with head room (`AgentHeight`) and no wall within `AgentRadius`: a column can hold several cells (ground under a bridge plus the deck = layers). Cells link to 8 neighbours when the height difference is at most `MaxStep` and two horizontal rays (just above a step, and at chest height) between them hit nothing, so a thin fence on a cell boundary cuts the link; diagonals also need both orthogonal links (no corner cutting), and links are made symmetric. Free paths: A* (octile heuristic), then string pulling (`LineClearFrom` walks the segment through the links, and the agent's sides must stay linked too), from the exact start to the exact goal. Grid paths (`grid = true`) keep cell centres and return costs (orthogonal 1, diagonal as given). `Closest` makes a blocked or unreachable goal end at the reachable cell nearest to it (X/Z), `MaxCost` cuts the path. Blocked cells (units, doors) are set by scripts and never baked. Baked lazily on the first `nav.*` call or by `nav.bake{}`, cleared on Start/Stop (bodies scripts add count from the next frame). `scene.screen_ray` / `scene.pick` turn a view point into a ray through the game camera (the app passes the aspect with `ScriptEngine::SetViewAspect`). The Viewport's View > Navigation Grid draws it during Play (green ground, blue upper layers, red blocked, lines for links). Measured on the Tactics test (26 x 26 columns, 596 cells): 3.8 ms Release, about 230 ms Debug. `Scripts/nav_test.lua` checks it against that level (`MDB_DEMO=tactics MDB_AUTOPLAY=1 MDB_TEST_SCRIPT=Scripts/nav_test.lua`, 22 checks).

- **Colour grading** (`PostSettings`, `tonemap.frag`, saved in the `post` settings section, Scene Settings > Post Processing > Color grading; the defaults change nothing). - **Volumetric fog** (`Renderer/VolumetricFog`, `SceneRenderer::VolFog` = `VolumetricFogSettings`, saved as the `volumetricFog` settings section, Scene Settings > Volumetric Fog; off by default, and a scene file without the section, or File > New, has none: it no longer carries over from the last level). Height fog (`Density` at and below `BaseHeight`, thinning by e every `HeightFalloff` m) with drifting value-noise wisps, raymarched at **half resolution** (`volfog.frag`, `Steps` samples up to `MaxDistance`, start jittered per pixel with interleaved gradient noise): each sample is lit by the sky (irradiance map or the procedural colour, x `u_Ambient`), the sun through **one tap of its shadow cascade** (so shadowed air is dark: light shafts) with a Henyey-Greenstein phase (`Anisotropy`), and point lights (no shadows). Output rgb = scattered light, a = transmittance, **twice per half-res texel**: one march along its 2x2 block's centre ray records the fog at the block's nearest and farthest depth (two RGBA16F targets plus an RG32F of the two distances; the steps are shared in proportion to the lengths). `volfog_composite.frag` interpolates each pixel between the two by its own distance, weighting the 4 nearest texels by whether their range holds that distance (its own block always does), and blends with ONE, SRC_ALPHA, entity IDs masked. (Marching each texel to one pixel of its block left thin branches in front of the fog band borrowing fog marched to the wrong depth: a dotted, crawling edge.) It takes `Scene::SetLightingUniforms` (the same sun, cascades and lights as lit.frag), so its shader has `Shader::QuietMissing` set (no warnings for lit-only uniforms). Drawn after see-through parts, before particles, from the shared depth copy (glass is fogged as the surface behind it). The village has a misty morning (density 0.032, falloff 1.8 m, a low sun behind the village); about 0.3 ms in Debug.
- **Model textures are shared between models** (`SharedTextures` in `Model.cpp`, weak pointers): an image file (by canonical path and write time) or an embedded image (by a hash of its bytes) is one GPU texture however many models use it. The village went from about 80 textures to 2.
- **Collider overlay cost.** The Viewport's collider overlay draws Mesh / Convex-hull colliders as a full wireframe only for the selected entity and its children (geometry cached per Renderable, `WireFor`); every other one is its bounding box. - **Renderables** (`Mesh`, `Model`) share the `Renderable` interface. This includes `GetLocalBounds`, the submesh/material hooks and `DrawInstanced` / `DrawSubmeshInstanced` (required: every scene draw is instanced).
- **Static mesh merging** (`Scene::BuildStaticBatches`, run by `GameSession::Start` after `on_create`). A Mesh Renderer marked `Static` that uses a **unique** mesh (no other static object uses that geometry) is merged with other unique static parts that share textures, alpha settings, material values and an 8 m cell into one world-space `Mesh`, drawn and culled as one object (entity ID -1: not clickable). Repeated meshes are never merged: measured, 2500 static cubes and spheres took 4.3 ms a frame instanced against 5.0 ms merged, because a merged chunk goes into every light view it touches. A group of one is not merged either. Merged entities get the runtime flag `Merged` (reset on copies) and are skipped by `BuildDrawList`. `Scene::Clear` / `Restore` (Stop) drop the batches; destroying a merged entity or removing its Mesh Renderer rebuilds them next frame (`OnMeshRendererGone`). Moving or recolouring a merged entity during Play is not seen. `Mesh` keeps a CPU copy of its vertices for this (`Renderable::GetPartVertices`). The demo levels mark still level geometry Static (`MarkStatic` in `DemoLevels.cpp`). Scripts: `e.mesh.static`, `add_mesh{ static = true }`, `scene.render_stats().static_batches / static_merged`.
- **Levels of detail** (`MeshRendererComponent::Lods` = `MeshLod{ Geometry, Distance }` nearest first (`SortLods`), `CullDistance`, runtime `LodLevel`: 0 = Geometry, i = `Lods[i-1]`, `Lods.size()+1` = culled). `BuildDrawList` picks the level (`PickLodLevel`) from the camera's distance to the middle of the main geometry's world box, times tan(fov/2)/tan(30 deg), divided by `Scene::Lod.DistanceScale` (settings section `lod`, written only when not 1; Scene Settings > Levels of Detail; Lua `scene.lod_scale`); going back to a finer level needs 5% nearer than its switch distance. The camera and every shadow view use that level; a level change sets `MovedNear` like movement (cached point shadows). A null level geometry falls back to the level before; with bones, a level that is not a skinned `Model` with the same `BoneCount` falls back to the main geometry. Everything else (LocalOffset, materials flag, wind height from the main geometry's bounds, frustum bounds) comes from the main geometry; `GetSurfaceAlpha` takes the drawn geometry. Entities with levels or a cull distance are never static-merged. JSON `lods` (`[{ geometry, distance }]`) and `cullDistance` only when set; Lua `e.mesh.lods` (copy; assign a list), `cull_distance`, `lod` (read only), `add_mesh{ lods, cull_distance }`; stats `RenderStats::LodReduced / LodCulled` (overlay, `render_stats().lod_reduced / lod_culled`); Viewport > Debug > LOD Levels (`Scene::TintLodLevels`, colours by level); Inspector > Mesh Renderer > Levels of detail. **Levels inside a model file** (`Model::LodCount / Lod(k) / LodDistance(k)`): before flattening, `DescribeNodes` (Model.cpp) tags nodes by name (`*_LOD<n>`; collision `UCX_/UBX_/UCP_/USP_*`, `*_COL / _collision / _collider`) or glTF node extras (`lod`, `collision`, optional `lod_distance`; read from the file's JSON by node name), children inheriting. If any node is tagged, the model is flattened by hand instead of `PreTransformVertices` (which joins every mesh of one material, levels included): per level, meshes joined per material; untagged meshes go into every level; level 0 = the lowest LOD number = this `Model`, the others are private-constructed `Model`s sharing the materials; collision meshes are not drawn but returned by `GetCollisionGeometry` (hull / mesh colliders, grass footprints). Untagged files load exactly as before; skinned files are not split. Names `model:<path>#lod<k>` (`ResourceLibrary` registry). `AssignModelLods(mr, model)` (Scene.cpp) fills `Lods` from the file: `lod_distance` x the LocalOffset scale, else box diagonal x 0.866 / (0.4, 0.2, 0.1 ...) (when it fills 40%, 20%, 10% of a 60 deg view); the editor's `AssignModel` (drops, placing, the Geometry combo, which now lists subfolders) and Lua `add_mesh` without `lods` call it, and `DropFileLods` removes the old file's own levels when the geometry changes. Inspector: the LOD picker lists the main file's levels first, "Use the file's N level(s)" / "Reset distances". No automatic simplification, no cross-fade. `Scripts/lod_test.lua` (16 checks: `MDB_SCENE=demo.json MDB_AUTOPLAY=1 MDB_TEST_SCRIPT=Scripts/lod_test.lua MDB_SAVE_DIR=<folder>`).
- **Batching and instancing** (`Renderer/DrawList`). Per-object values (model and normal matrix, colour + alpha, metallic/roughness, emissive, entity ID, unlit) live in an `InstanceData` storage buffer (std430, binding 0). `lit.vert` and `shadow.vert` read `u_Instances[u_Indices[u_InstanceBase + gl_InstanceID]]` (indices: binding 1, one list per view) and pass them to the fragment shader as flat varyings, so they are no longer uniforms. A `DrawBatch` is a run of instances sharing geometry part, textures, alpha mode/cutoff and bones, drawn with one `glDrawElementsInstanced`. Opaque and shadow lists are sorted by state; the transparent list stays back to front, and only equal neighbours merge. Skinned entities are batches of one (their own `u_Bones`). Shadow batches drop the textures they do not alpha-test, so opaque casters merge across materials. **Shadow culling:** `GatherShadowViews` lists the shadow views in a fixed order (each shadowed point light: 6 faces, then the sun), used both to build and to draw them. A caster goes into a view only if it is within the light's reach (bounding sphere vs `PointFar`) and inside that face's (or the sun box's) frustum. The Viewport stats overlay counts the skipped pairs ("Shadow skipped"). Stats: draw calls, instances and culled (Viewport stats overlay; scripts use `scene.render_stats()`, last frame).
- **Transparency.** `AlphaMode` (`Material.h`): Opaque, Cutout (discard below `AlphaCutoff`), Blend (see-through). A Mesh Renderer has `Alpha`, `Opacity`, `AlphaCutoff` and `CastShadows`; with model materials the stronger mode wins and alphas multiply (`GetSurfaceAlpha` in `Scene.cpp`). Alpha = texture alpha x material alpha x opacity. Blend output is premultiplied: the diffuse part scales with alpha, reflections stay (glass), and everything fades near 0. Shadows alpha-test (Cutout at its cutoff, Blend at 0.5). glTF `alphaMode`/`alphaCutoff` are imported; other formats with opacity < 1 become Blend. Mesh textures can be any image: `"texture:Textures/fence.png"` (`ResourceLibrary::LoadTexture`). Scripts: `e.mesh.opacity` (below 1 switches Opaque to Blend), `alpha_mode`, `alpha_cutoff`, `cast_shadows`, and the same keys in `add_mesh`.
- **Specular factor** (`Material::Specular` from glTF `KHR_materials_specular` `specularFactor`, times `MeshRendererComponent::Specular`; Inspector slider, JSON `specular` only when not 1, Lua `e.mesh.specular` / `add_mesh{ specular }`). **assimp drops `specularFactor` 0** when the colour is the default (its glTF2 importer treats that as "not set"), and 0 is what Blender's Specular IOR Level 0 exports. So `Model.cpp` reads the factor itself from the .gltf JSON or the .glb JSON chunk (`ReadGltfSpecular`, nlohmann), matched by material index and checked by name. It travels as `InstanceData::Info.z` = 1000 x (1 - specular), so zero, the default of every instance, means full specular; it is also part of the static-merge key. `lit.vert` puts it in `v_Surface.z` (`foliage.vert` writes 1). `lit.frag` follows the extension: F0 = 0.04 x specular for non-metals, and F90 = specular (`FresnelSchlick`, `Shade` and `EnvBRDFApprox` take F90); metals keep F90 = 1. At 1 the result is the same as before. Found on the willow bark: roughness 1 and metallic 0, yet a grey sheen came from the 4% base reflection and the grazing Fresnel, against a very dark albedo (sRGB mean 78, 44, 16).
- **glTF COLOR_0: architecture tint vs vegetation wind** (Game Art Library convention, `D:\Projects\Game Art Library\README.md`). `ClassifyVertexColors` (Model.cpp) reads the `category` extra (asset, scenes, nodes, meshes, materials; first found wins, a conflict warns; the library puts it on the root node as a path, e.g. `"Architecture/Castle_Stone"`, `"Nature/Trees"`) and a `wind` extra: first path part `architecture` = **Tint**, a `wind` extra or `nature` / `vegetation` = **Wind**, else Ignored (also for files without COLOR_0, and non-glTF). Two vertex slots, both RGBA8 in a uint32 (`ShaderDataType::UByte4Norm`, fixed locations through `BufferElement::Location`): `Vertex::Color` (location **5**, sRGB-encoded by `PackVertexColor`, default white) and `Vertex::Wind` (location **6**, linear, `PackVertexWind`, default 0); `Vertex` is 40 bytes, `SkinnedVertex` 72, and `Mesh` asserts that its layout stride equals the struct (a missing attribute once smeared every mesh across the screen while all tests still passed). Tint: `lit.vert` does `v_Color = inst.Color * a_VertexColor` (both sRGB-style; `lit.frag`'s pow 2.2 distributes over the product); VAOs without location 5 read the generic value, set to white once in `VertexArray`'s constructor. Wind: `Model::HasVertexWind()` (the `Renderable` hook, copied to its LOD models) -> `InstanceData::Info.w` = 1, and `ApplyWind` (lit.vert and shadow.vert) then takes R as the main bend weight (instead of height^2), G x the per-branch phase B for a branch sway (about 1.2% of the tree's height, along the wind with some across and up/down), A for the leaf flutter (instead of height). The Mesh Renderer's `Wind` amount still scales it, and the editor's `AssignModel` / Lua `add_mesh` (unless `wind` is given) set it to 1 for such models. Static merging copies whole vertices. `shadow.vert` ignores vertex alpha. Checked with the library's castle wall (darker toward the ground: rising damp, ratio 0.99 top to 0.96 base against an untinted copy) and Tree_Broadleaf_01 (not tinted; sways, base still).
- **Alpha-tested mipmaps and anisotropic filtering** (`Texture2D`). Plain mipmaps average thin cut-out leaves into faint alpha below the cutoff, so foliage thinned out and vanished with distance. For example, the willow's leaves at cutoff 0.5 kept 60% of their pixels at mip 4, 27% at 5 and 8% at 6. A texture with any alpha below 255 keeps its full-size pixels. The first time `GetSurfaceAlpha` sees it on a Cutout part, `PreserveAlphaCoverage(cutoff)` rebuilds the mip chain on the CPU and frees the copy. Colour is box-filtered in linear light for sRGB, and each level's alpha is scaled so the full-size share of pixels reaches the cutoff (Castaño). The scale is only ever upward, because broad leaves gain coverage as they shrink. The first cutoff wins. The hook must come **after** the model material is merged into `SurfaceAlpha`: the material usually decides that a part is Cutout (a first version placed it before, so it never ran on model leaves). Every texture also gets up to 16x anisotropic filtering: glad is 4.5, so the enums `0x84FE` / `0x84FF` are written out. Measured on the village's distant willows (Textured view, leaf-coloured pixels against the sky): 1,562 before, 7,918 with the coverage fix, 9,097 with anisotropic filtering as well.
- **Double-sided** (`MeshRendererComponent::DoubleSided`, plus `Material::DoubleSided` from glTF `doubleSided` / assimp `AI_MATKEY_TWOSIDED`). A part is double-sided if either says so (`SurfaceAlpha::DoubleSided`). The flag is part of the batch state (`DrawBatch::DoubleSided` and the static-merge key), so `CullSwitch` in `Scene.cpp` turns culling off only for those batches, in the camera passes and both shadow passes. It never turns on culling that was off (X-ray wireframe). `lit.frag` flips the geometric normal on back faces when `u_DoubleSided` is 1. JSON writes `doubleSided` only when true, so no new prefab overrides appear. Inspector: a checkbox beside Static. Lua: `e.mesh.double_sided`, `add_mesh{ double_sided }`. **Blender writes `doubleSided: true` whenever a material has Backface Culling off, which is its default.** Every village kit file had it, which would have drawn the back of every piece. `export()` in `village_kit.py` now removes the flag, and the existing kit files were patched the same way.
- **Animation events and layers.** `AnimatorComponent::Events` (`AnimEvent{ Clip, Time, Name }`) fire when playback crosses their time, forwards or backwards and across loops (`AdvanceClip` in `Scene.cpp`), for the base clip and every layer; a non-looping clip also fires `"end"`. Fired events wait in `Animator::Fired` (cleared each update) and `ScriptEngine::DispatchAnimationEvents` (called by `GameSession::Update` right after `Scene::OnUpdate`) delivers them as `on_anim_event(self, name, clip)`, or plays `"sound:<path>"` events at the entity. `Layers` (`AnimLayer{ Clip, Mask, Weight, Speed, Loop }`) are applied in order after the base pose: each replaces the pose of its mask (a node and its descendants, `Model::SubtreeMask`; "" = all, an unknown name = nothing) by `Weight`. Weights can fade (`layer_weight(n, w, seconds)`). An `Additive` layer instead adds its clip's change from its first frame, scaled by the weight (rotation: base * slerp(identity, inverse(first) * now, w)). **Root motion** (`RootMotion`, `RootBone` "" = the topmost node the base clip translates, `Model::RootMotionNode`): each frame the root bone's sideways change in the base clip (converted to entity space through `LocalOffset * Model::ParentRestGlobal`) moves the entity with `SetWorldPosition`, whole loops adding the clip's full travel, and the bone is held at its first-frame sideways position in the pose; vertical movement stays in the animation. It moves the transform, so use no body or a kinematic one. The Fox clips are in place (they sway and surge but end where they start), so the demo does not use root motion. **IK** (`AnimatorComponent::IK`, `AnimIK`, `SolveIK` in `Scene.cpp`) runs on the final pose, after layers, in model space (targets go through the inverse of entity world * `LocalOffset`); it also runs in Edit mode. Targets are an entity (`TargetID` = its `IDComponent`, plus `Target` as an offset) or a world point. *Look*: the head's forward is the direction that points along the entity's +Z in the rest pose; the turn is shared by `Chain` bones (top first, each taking its share of what is left) and clamped to `MaxAngle` from the entity's facing. *Limb* (two-bone) works in three exact steps with positions refreshed between them: bend the middle joint to the needed length, swing the root bone onto the target line, then twist around that line towards `Pole` (entity space). Measured on the Fox: a paw lands on its target exactly, an out-of-reach arm ends straight and within 0.02 deg, and a look target is faced exactly within the limit. A bone is turned by a model-space rotation through its parent (`RotateNode`: L = P^-1 * q * P * L), which assumes uniform node scale. The node globals are kept (`Animator::Globals`) for `Scene::BonePosition` / `BoneForward` (Lua `bone_position`, `bone_forward`). The demo fox watches the player ball (IK 1) when it comes within 4 m. Both are saved with the Animator (only when present) and edited in the Inspector (Animator > Layers / Events). The demo fox has footstep sound events and an additive Survey layer on `b_Neck_04` that `wander.lua` fades in while walking.
- **Animation graphs** (`Animation/AnimGraph`, `Editor/src/AnimGraphEditor`, files `Assets/AnimGraphs/*.json`). `AnimGraph` = `Params` (float / int / bool / trigger, defaults) + `Layers`; each `AnimGraphLayer` has a mask bone, weight (x an optional `WeightParam`), `Additive`, an `Entry` state id, `States` (`AnimState`: a clip or a `Blend1D` of `AnimBlendPoint`s {clip, threshold, speed} on `BlendParam`; speed, `SpeedParam`, loop; ids unique per layer) and `Transitions` (`From` = state id or `AnyState` -1, `To`, `Duration`, `HasExitTime`/`ExitTime` 0..1, `Conditions` {param, op `> < == != true false`, value}, all must hold). `AnimatorComponent::Graph` (path, JSON `graph` only when set) with runtime `GraphData` (`shared_ptr<const AnimGraph>`, never changed in place), `Params` (name -> float, filled with defaults) and `GraphLayers` (`AnimGraphLayerState`: state, phase 0..1, from-state + its phase, fade, transition index, state time). `Scene::UpdateAnimations` calls `EvaluateAnimGraph` instead of the Clip path when `GraphData` is set; it returns the base layer's leading clip (`AnimGraphBase`) so root motion works the same; the component's own Layers, IK and Events still go on top. **Evaluation per layer:** enter the entry state if the state is unknown (also after live edits deleted it); advance: a state's phase moves by dt x speeds / its **cycle length** (the clips' durations at their point speeds, weighted), and the clip with the most weight runs it through `AdvanceClip` (moved here from Scene.cpp, shared), so its events and "end" fire; a blend uses the two points around the parameter (clamped at the ends) sampled at the same phase (feet in step); the from-state advances silently and the fade by dt / duration (dt 0, Edit mode: instant). The pose is sampled **before** transitions, which are checked after advancing: Any State ones first (allowed during a fade, never to the current state), then the current state's (not during a fade), in list order; exit time = phase >= exit (or a loop wrapped, for exit 1); a transition with neither conditions nor exit time is never taken; triggers in a taken transition's conditions reset; entering fires `("enter", state name)` into `Animator::Fired`, so scripts get `on_anim_event(self, "enter", name)`. Layer 0 is the pose; others blend over `SubtreeMask(mask)` by weight, or add the change from the state's phase-0 pose (same blend weights). **Loading:** `ResourceRegistry::LoadAnimGraph` -> `ResourceLibrary::LoadAnimGraph` (cached by write time; `SetAnimGraph` installs the editor's live copy, which wins until replaced). **Editor:** the Dialogue Editor's canvas (pan/zoom/grid, header-coloured nodes, right-edge pins, popups, JSON-snapshot undo committed when nothing is held) with state nodes, Entry / Any State pills and transitions as straight arrows with a midpoint arrowhead, offset sideways so A->B and B->A separate (self-transition: a loop); side panel for layers and parameters (rename updates every use), properties panel and `AnimGraph::Issues`. Every change calls `OnChanged(path, copy)` (`Publish`, when the JSON differs), and main.cpp's callback calls `SetAnimGraph` and swaps `GraphData` on every animator with that path, so edits apply while playing. `LinkAnimGraphEditor` (main.cpp, every frame the window shows) passes the watched Animator (selected entity's if it uses the file, else the first) and the clips / bones of its model (or the selection's) for pickers and clip checks. Inspector > Animator: Graph combo (+ drop of `Kind::AnimGraph`, "ANIM" badge, double-click opens), Edit graph, layer states and parameter values; Clip / Loop / Blend time / Time hide with a graph. Lua: `add_animator{ graph }`, `a.graph`, `set`, `get`, `trigger`, `reset_trigger`, `state([layer])`, `state_time`, `phase`, `in_transition`, `play_state(name [, layer, blend])`. Example `AnimGraphs/fox.json` (Idle / Locomotion Walk 1.1 - Run 3.6 / one-shot Look from Any State on trigger `look_around`, exit time back; additive Head layer on `b_Neck_04` x `head`), driven by `Scripts/wander_graph.lua`; `Scripts/anim_graph_test.lua` (17 checks, spawns its own fox: `MDB_SCENE=demo.json MDB_AUTOPLAY=1 MDB_TEST_SCRIPT=Scripts/anim_graph_test.lua`).
- **Skeletal animation.** A model file with bones (glTF/FBX via assimp) keeps its node tree: `Model` holds skeleton nodes (parents first), bones (node + offset matrix), clips (keys in seconds) and skinned submeshes (`SkinnedVertex`: 4 bone indices at location 3, `ivec4`, and 4 weights at location 4). Changing `Clip` cross-fades (lerp/slerp of node poses). The result is a bone palette that `Scene::SetSkinning` uploads as `u_Bones[128]` + `u_Skinned` for both `lit.vert` and `shadow.vert`; a skinned model with no Animator uses its rest palette. Bounds and colliders use the rest pose. Scripts: `e.animator` (`play(name, blend)`, `clip`, `speed`, `time`, `clips()`, `duration()`), `e:add_animator{}` and `e:add_mesh{ geometry = "model:Models/Fox.glb", fit = 1.6 }`.
- **Scene files** (`Assets/Scenes/scene.json`) store resource **names** ("cube", "plane", "sphere", "model", "model:Models/Fox.glb" for any model file, "checker", "texture:Textures/x.png" for any image), mapped back to live resources by `ResourceLibrary` (models are loaded once, on demand). A `settings` block (`SceneSettings`) holds the environment map name, sky, ambient, post, AO, bloom, shadows, gravity and the editor camera. Every section and field is optional, so older files load fine. The editor fills it with `GatherSettings` and `ApplySettings`. Load is queued and applied at the start of `OnUpdate`. `demo.json` is the saved script demo. In version 3, an unmodified prefab instance is stored as `name` + `transform` + `prefab` and gets its components from the prefab file when the scene loads.
- **Prefabs** (`PrefabLibrary`, full format in `Prefab.h`). A prefab is an entity **with its children**, stored as a tree of nodes in `Assets/Prefabs/<name>.json`. The root has the components and default rotation/scale. Each child node has a stable `key`, a name, a local transform, components and children (version 2; version 1 files have no children). Every entity of an instance links to its node: `PrefabComponent{ Path, Node }`, where 0 is the root. Each part is its node plus **overrides**: changed fields, added components (whole), removed ones (`null`), and for child parts a moved local transform (`DiffComponents` / `MergeOverrides`). Scene files store links, overrides, a child's transform only if moved, and `removedNodes` (child nodes an instance deleted) on the root. On load, `SyncInstance` adds parts the prefab gained and unlinks parts it lost. Apply (from any part) writes the whole instance. Every other instance keeps its overrides on top of the new prefab, gains new parts and keeps (unlinked) dropped ones. Revert and `RevertOverride` work per entity. Cached prefabs are re-read when the file changes and are normalised through a scratch entity. If a prefab cannot be read, Save writes a full copy. Prefabs do not nest: saving a group makes all of its children parts of the new prefab.

## Render pipeline (per frame, `SceneRenderer::Render`)

0. `Scene::BuildDrawList`: every part that the camera or a light can see goes into a `DrawList` once, with its per-object data. Each view (the camera, every point-light cube face, the sun) gets its own index list into it, sorted into batches. Both are uploaded as storage buffers.
1. Shadow passes: up to 4 point lights (cubemap array, 6 faces each) and one sun (cascaded, below) (ortho 2D map). **Point shadows are cached**: a still light re-renders its cube only every `ShadowSettings::PointUpdateInterval` frames (default 2, staggered across lights; Scene Settings > Shadows > Update every, saved as `pointInterval`). Its layer is forced the same frame if it is new, moved, its slot changed or `PointFar` changed, and the next frame if a shadow-casting part moved or is skinned within reach (`ShadowContext::Cache[i].MovedNear`, set in `BuildDrawList` before the cull `continue`, from `DrawList::PrevWorld`; wind sway does not count). The cache lives in `ShadowContext`; `GatherShadowViews` takes the context and leaves out the faces of lights not due. They are **sampled with hardware PCF**: the cube array has `GL_COMPARE_REF_TO_TEXTURE` with linear filtering, and `lit.frag` uses `samplerCubeArrayShadow` with 8 corner taps instead of 20 single compares (only `lit.frag` samples it; the sun map stays a plain sampler because `volfog.frag` reads it raw).
   **Depth pre-pass** (`SceneRenderer::DepthPrepass`, default on): the opaque list (`lit.vert` + `depth_prepass.frag`, cut-outs alpha-tested) and the grass (`foliage.vert` + the same, `FoliageRenderer::Render(..., update = true)`) are drawn depth-only with colour masked. The lit opaque and grass passes then run with `GL_LEQUAL` and depth writes off, so each pixel is lit once. Both vertex shaders have `invariant gl_Position`, and the grass's lit call passes `update = false` so wind time and trampling advance once a frame. The selection-outline depth copy is taken between the pre-pass's opaque and grass parts.
2. Scene into an **HDR framebuffer** (RGBA16F color, an `R32I` entity-ID attachment used for click picking, and a depth texture).
   The shader is **PBR metallic-roughness** (Cook-Torrance GGX), with normal, metal/rough and emissive maps.
   Ambient comes from **IBL**: irradiance and prefiltered cubemaps baked from an HDR panorama, or a procedural sky if none is loaded.
   Foliage (grass clumps, `FoliageRenderer`) is drawn right after the opaque scene. The skybox is drawn after that, then decals (projected from a copy of the depth). Then see-through (Blend) parts, then volumetric fog (`VolumetricFog`, when enabled), then particles. See-through parts are sorted back to front by
   bounds centre, premultiplied blending, depth test on, depth writes off (`Scene::Render(..., RenderPass::Transparent)`).
3. SSAO from depth, then a blur, at **half resolution**, computed **right after the opaque scene and grass** (`aoOn` in `SceneRenderer::Render`) and multiplied into the HDR colour there (`ao_apply.frag`, blend DST_COLOR / ZERO, entity IDs masked): before the sky, decals, glass, volumetric fog and particles, which it must not darken, and before the TAA resolve, which averages its noise (with TAA its per-pixel rotations change each frame, `u_NoiseOffset`). It used to multiply the finished picture in the tone map, so it darkened the fog and flickered with the jitter: measured on a still village (fog on), pixels changing by more than 3/255 per frame went from 9.4-12% with AO (6.4-6.7% without) to 4.7-5.4% (4.0-6.9% without). The tone map now reads the AO buffer only for Debug > Ambient Occlusion Only.
4. Bloom: a down/up chain, with a soft threshold, a Karis average and a per-pixel brightness ceiling to stop fireflies.
   **TAA** (`PostSettings::TAA`, default on, saved as post `taa`; Rendered view only). Every pass draws through `view`, a copy of the camera with `Camera::SetJitter`: a sub-pixel projection offset, 8 Halton (2,3) points. The opaque scene and grass write **motion vectors** to HDR attachment 2 (RG16F, UV now − UV last frame). `Framebuffer::SetVelocityWrites` enables draw buffer 2 only around those passes; everything else leaves it at `kNoVelocity`. `lit.vert` computes the vectors from unjittered `u_CurViewProjection` / `u_PrevViewProjection` and `InstanceData::PrevModel`. `InstanceData` is now 256 bytes: `BuildDrawList` fills `PrevModel` from `DrawList::PrevWorld`, a per-entity map swapped every frame; static batches are identity. Wind uses the previous time (`Scene::WindTimePrev`, `u_SceneWindTimePrev`). Grass writes camera motion only. Skinned limbs get their entity's motion only (the previous bone pose isn't kept). Then `taa.frag` (`SceneRenderer::Impl::ResolveTAA`, ping-pong RGBA16F history) runs. It takes the motion of the nearest depth in 3x3; where none was written (sky, glass) it reconstructs the motion from depth and the two view-projections. It samples the history with Catmull-Rom, clips it to the neighbourhood's colour box (YCoCg, mean ± 1.1 sigma, colours compressed by c/(1+luma) first), and blends 10% of the new frame (up to 25% when fast). Its output replaces the HDR colour for bloom and the tone map; FXAA is skipped. `SceneRenderer::ResetTemporalHistory` runs on camera cuts (level loads in both apps, switching the editor to or from the game camera). The selection mask is drawn **unjittered** (a steady outline), so `select_mask.frag` tests against the farthest depth in 3x3. Debug: `ShowMotionVectors` (Viewport > Debug > Motion Vectors, `MDB_MOTION_VECTORS=1`; 16 px = full colour; the post chain is plain for it). **Pitfall:** `glClearTexImage` with float data wrote -infinity into the RG16F velocity target on this NVIDIA driver, which turned every sky pixel invalid. `Framebuffer::Clear` clears it through the framebuffer instead (`glClearNamedFramebufferfv` on draw buffer 2, enabled for the clear). Measured on the village: pixels that change by more than 8/255 between two still-camera frames went from 7.2% to 3.7% (the rest is wind and film grain), with no measurable frame-time cost (13.2 ms both, Debug).
5. Post pass: AO, plus bloom, exposure, tone map (ACES default), gamma.
6. FXAA pass, only when TAA is off. The result is shown in the ImGui Viewport panel.

**Frame cost, village (Release Game, 1920x1080, RTX 2060, 4 shadowed lamps: 3 still, 1 orbiting).** 15.2 ms (66 FPS) became 11.0 ms (91 FPS). Each step: hardware PCF 15.2 -> 14.2, depth pre-pass -> 12.1, point-shadow interval 2 -> 11.4, half-resolution SSAO -> 10.6 to 11.0 (runs vary with where the orbiting lamp is). GPU stages now: shadows 3.0 (the sun's 4 cascades about 1.7), lit opaque 2.0, grass 1.7, volumetric fog 1.6, pre-pass 0.8, TAA 0.4, SSAO 0.3, bloom 0.3. Measured trade-offs, left to content: interval 4 gives 10.9 ms; point shadows off entirely gives 9.1 ms. Tried and not worth it: skipping the sun shadow lookup (0.15 to 0.4 ms). Lighting was the cost, not geometry: lit.frag with no lighting made opaque 0.85 and grass 0.54 ms.

Color spaces: lighting is done in linear space. Color pickers and albedo colors are sRGB-style and converted in the shader. Albedo and emissive textures are sRGB textures. Normal and metal/rough textures are linear.

## Editor

- **Layout** (Unity / Godot style). The editor starts as a maximized window (F11 or Window > Full Screen switches to borderless full screen and back; `WindowProps::Maximized`, kept across the switch). A **main menu bar**: File (New Ctrl+N, Open Scene, Save Ctrl+S, Save As Ctrl+Shift+S, Example Levels (Examples project only), New / Open / Recent Projects, Show Project in Explorer, Build Game, Exit), Edit (Undo / Redo named after the step, Duplicate, Delete, Frame Selected, Reload Shaders), Create (Empty, Cube, Sphere, Plane, Point Light, Sun, Camera, Physics Box / Ball, Material Grid, Prefab; also the Hierarchy "+" button and right-click), Play, Window (show panels, Hide Panels F1, Full Screen F11, VSync, Reset Layout) and Help (Controls, About), with the scene file, `*` for unsaved changes and FPS on the right (the window title shows the project and scene). A **toolbar** (`BeginViewportSideBar`): Select / Move / Rotate / Scale, Local / World, Snap; drawn Play / Pause / Step icons in the centre; status and the game-camera switch on the right. Dockable **panels**: Hierarchy (left; "+", search, right-click Create, row menu Duplicate / Delete / Unparent / Frame), Viewport (centre; its own View / Debug / Camera menu and a stats overlay), Console (below; every log line through an in-memory spdlog sink, `Log::History`, with level filters, search and auto-scroll), Inspector and Scene Settings (tabs on the right; Scene Settings holds environment, shadows, post-processing, physics, audio and script status), and **Assets** (a tab with the Console; `Editor/src/AssetBrowser`): a folder tree, breadcrumb, search over all assets, tiles (texture thumbnails, typed badges) or a list. Double-click opens a folder or scene, places a model / prefab, plays a sound, sets a sky (.hdr) or opens the file with its program. Right-click: New Script (from a template, named right away), New Folder, Rename, Delete (to the Recycle Bin), Show in Explorer, Copy Path; renames and deletes do not update references. Files drag as payload `"MDB_ASSET"` (a path relative to Assets): onto the viewport (a model / prefab lands on the surface under the mouse, from the depth buffer: `Framebuffer::ReadDepth`, `PointAt`; a texture / script / sound goes to the object under the mouse; an .hdr becomes the sky), onto a Hierarchy row (a model / prefab becomes its child, others go to that entity) or empty space, and onto the Inspector's Geometry, Texture, Script, Clip and Sky map fields (`AssetBrowser::AcceptDrop` only accepts the right kinds). Shell calls (open, Explorer, Recycle Bin) are in `Editor/src/Platform.cpp`, the only file that includes `<windows.h>`. Style: `ApplyEditorStyle`, Segoe UI 17 px (Consolas for the Console and stats). `MDB_WINDOWED=1` starts in a plain 1600 x 900 window (screen captures of a full-screen OpenGL window show a stale frame).
- **Viewport shading and selection outline** (`SceneRenderer::Mode` = `ViewMode` Wireframe / Solid / Textured / Rendered, `XRay`; `Highlight`). These are editor view settings and are not saved. The editor forces Rendered while looking through the game camera. Choose a mode with the Viewport's Shading menu, the buttons on the right of its menu bar, or keys 1-4 (1 again toggles X-ray). **Solid / Textured**: `lit.frag`'s `u_ViewMode` (1 / 2; the game never sets it, so it is 0) takes an early branch with a camera-following studio light (white peaks at 0.8). They build the draw list without shadows, skip the sky, decals (in Solid), volumetric fog and fog of war, and post-process with a plain `PostSettings` (clamp, no bloom or grading; AO kept). **Wireframe**: `lit.vert` + `wire.frag`. One fill pass writes depth and entity IDs with colour masked off, so clicks pick surfaces. Then a `GL_LINE` pass draws with polygon offset and depth writes off; X-ray turns off the depth test and culling. No foliage or particles. **Outline**: the editor fills `Highlight` (entt integrals) with the selection and every descendant that has a Mesh Renderer. `BuildDrawList` copies those visible parts into `DrawList::Selected` (merged static parts too, from their entities). `select_mask.frag` (lit.vert, `RenderPass::Selected`) draws them into an RG8 mask with MAX blending: R where the depth is at most `SelDepth` (a depth copy taken right after the opaque pass, before grass, decals and glass, so grass never hides a selection; `lit.vert` has `invariant gl_Position` for this), G where hidden. `outline.frag` then draws a soft 2 px line onto the final post-processed image (`PostProcess::GetOutputFramebuffer`), dimmer where hidden, plus a faint fill over hidden parts and a 1 px line inside the mask where the entity ID (`Framebuffer::GetEntityIDAttachment`) changes, so touching selected objects stay apart. Test hooks: `MDB_VIEW_MODE=wireframe|xray|solid|textured|rendered`, `MDB_SELECT=<name>[,<name>...]` (the first entity of each name; the last is active).
- **Maya-style controls.** Alt+LMB orbit, Alt+MMB pan, Alt+RMB or wheel dolly. **Q** select, **W/E/R** move/rotate/scale gizmo. **F** frame selected. **N** spawn a cube. **Delete** deletes the selection. **F5** reloads shaders, and scripts too while playing. **Ctrl+Z** / **Ctrl+Y** (or Ctrl+Shift+Z) undo and redo, **Ctrl+D** duplicates the selection, **Ctrl+S** saves. **F1** hides the side panels. There is no WASD fly camera (it was removed on purpose).
- **Undo/redo** (`EditorHistory`, Edit mode only). The editor never records individual edits. After any interaction (mouse released, a widget active, a key pressed, the gizmo used) it sets `m_MaybeChanged`. At the start of the next `OnUpdate` with nothing held, `Track()` compares the scene to the current state as text (names, transforms, prefab links, components via `EntityJson`). If they differ, it stores a new state, a whole-scene `SceneSnapshot` (limit 100). So every scene edit is undoable with no per-feature code, and a drag or typed name is one step. Labels such as "Move Player", "Delete Lava" or "Build Coin Rush" come from the difference, or are passed in. Scene settings (environment, post) and the editor camera are not tracked. The title shows `*` for unsaved changes. Quit (Esc or the close button, via `Application::OnCloseRequested`) and Load ask first.
- **Play mode** (Ctrl+P, the toolbar's Play / Pause / Step buttons, or the Play menu). Play snapshots the scene and runs Spin, Orbit and physics. Pause and Step are available. Stop restores the snapshot, and Escape stops Play first and quits only in Edit mode.
  Edit mode is frozen except that orbiting lights sit at their orbit position.
- **Game camera.** During Play the viewport renders from the primary `CameraComponent` entity, which looks along local -Z like the sun. Turn this off with Play > Play Through Game Camera (or the toolbar's "Game camera" box). While looking through it, the colliders, gizmo and click-picking are hidden, and editor shortcuts are off except Esc, Ctrl+P, F1 and F5, so games can use those keys. In the editor, camera entities are drawn as frustum outlines, suns as a ring of parallel arrows along local -Z and point lights as a lightbulb icon in their colour (`DrawSunGizmos` / `DrawPointLightGizmos`, ImGui over the Viewport, never rendered; clicks and selection boxes pick them, `LightGizmoAt`; Viewport > View > Light Gizmos). Lights have no mesh: `SceneSerializer::Load` drops the old marker (an unlit "cube" Mesh Renderer on a light, scale reset to 1) from older files. Viewport > View > Colliders is off by default.
- **Model preview** (`Editor/src/ModelPreview`). Clicking a model file in Assets (`AssetBrowser::Selected()`, Kind Model) shows it at the bottom of the Inspector: the entity fields go in a scrolling child (` Drag an entity onto another to parent it, or onto the empty space below to make it a root (the world placement is kept). The Inspector's Transform shows local values, with "Relative to <parent>" and an Unparent button.
- **Multiple selection** (`m_Selection` in `Editor/src/main.cpp`). `m_Selected` is the *active* entity (the Inspector, the gizmo pivot, undo history) and is always the last entry of `m_Selection`. `SyncSelection` (each frame and before selection work) drops dead handles, and if `m_Selected` was set to something outside the set, the set becomes just that, so the old single-select paths (spawn, place asset, undo) need no changes. Clear `m_Selection` wherever handles are rebuilt (undo / redo, Stop, level loads). `SelectionRoots()` are the selected entities with no selected ancestor; delete, duplicate, unparent, group, Hierarchy re-parenting and the gizmo work on them (the gizmo applies `new * inverse(old)` of the active entity to each, so they move, rotate and scale about its pivot). Viewport: the selection happens on mouse release; a drag past 4 px is a box (`Framebuffer::ReadEntityIDs`, the distinct IDs in a rectangle), and Ctrl or Shift adds or toggles. Hierarchy: `RowClicked` (Ctrl toggles, Shift selects the range in `m_RowOrder` from `m_RowAnchor`, a plain click on a selected row waits for release unless a drag started). `GroupSelected` (Ctrl+G) makes an empty "Group" at the mean position, under the common parent if there is one. Ctrl+A selects all. The collider overlay draws full mesh wireframes only for the active entity (all of them cost too much).
- **Prefabs in the editor:** Hierarchy "+ Prefab" places an instance. Instances are listed in blue. The Inspector shows the link ("Prefab" or "Part of prefab") with its overrides (each with a Revert button), Apply to prefab (the whole instance), Revert all and Unpack, or "Save as prefab..." for a plain entity. Scripts use `scene.spawn_prefab("name", pos)`.
- **Example levels** (File > Example Levels): **Tactics test** (`tactics_test.json`, `tactics.lua` + `tactics_camera.lua`): free click-to-move exploring and turn-based grid combat on one nav grid (terraces and a bridge, a ramp, steps, a fence, crates; C or an ambush starts combat, blue = reachable, orange = path preview with cost, Space ends the turn, enemies walk to the hero; Q / E turn the camera). Its glowing pad (`exit.lua`, target in the entity name `Exit: <file> > <entry>`) leads to the **Tactics cellar** (`tactics_cellar.json`) and back; both have a chest (`chest.lua`, named `Chest: <item>`: gold into `game.gold` and that item into the bag). The UI is laid out: a HUD panel, an auto-width toolbar, a framed save-slot panel (F6 / F9 quicksave / quickload), the inventory (`inventory.lua`: I, a 16-slot bag and 3 equipment slots in `game`, drag and drop, tooltips, right-click drinks a potion; other scripts give items through `game.pending_loot`) and a talking **Sage** (`npc.lua` playing `Dialogues/sage.json`: T near it; first-meeting branch, a shop with a greyed-out choice, a quest that sends `quest_started` (tactics.lua announces it), a `magic` event npc.lua answers with sparkles, a scrolling long answer). **Script demo** (`demo.json`, with an animated fox running `wander.lua`, a cutout fence and a stained-glass panel) and **Coin Rush** (`coin_rush.json`), a small game. In Coin Rush, a title screen (Play / Quit buttons) leads to: collect 8 coins in 2 minutes, then reach the goal. The HUD has a coin icon and a time bar, and the end screens have Play again / Quit buttons. It has lava, a sweeper and a bounce pad, and R retries. Its scripts are `game.lua` (rules and HUD, state in `shared`), `follow.lua`, `player.lua`, `coin.lua`, `goal.lua`, `hazard.lua` and `bouncer.lua`.
- Physics runs only during Play, at a fixed 60 Hz with interpolated transforms. Body types are Static, Dynamic and Kinematic. **Lock rotation** (`RigidBodyComponent::LockRotation`, dynamic only; JSON `lockRotation` only when set; Inspector next to Trigger; Lua `add_body{ lock_rotation = true }`, read `e.body.lock_rotation`) creates the Jolt body with `mAllowedDOFs` = translation only, so contacts and forces never turn it: for characters. Shapes are Box, Sphere, Capsule (Size.x diameter, Size.y total height, along local Y), Convex hull, Mesh and None. **Compound colliders:** a body also gets every descendant's `ColliderComponent` (stopping at descendants with their own Rigid Body), placed where those entities are, as one Jolt `StaticCompoundShape` (see `PhysicsWorld::BuildShape` / `CollectColliders`). Hull and mesh use the entity's mesh with its LocalOffset and world scale, are cached per geometry and scale for each Play, and fall back to a box (with a warning) without a Mesh Renderer. Any body can be a Trigger (drawn in magenta). The overlay draws hull and mesh colliders as a faint wireframe (at most 2000 triangles, sampled). **T** throws a ball during Play. Collider outlines are drawn with ImGui.

## Conventions

- DSA OpenGL calls (`glCreate*`, `glNamed*`). Wrapper classes own GL objects (RAII) and are non-copyable.
- Shader uniforms go through `Shader::Set*`, which uses `glProgramUniform*` and caches locations.
- Logging macros: `ENGINE_INFO/WARN/ERROR` (engine side) and `LOG_INFO/WARN/ERROR` (game side).
- State changes that invalidate the frame (environment bake, play start/stop) are queued as commands and applied at the start of `OnUpdate`, never in the middle of building the ImGui frame.
- Pending fullscreen passes use a vertex-less triangle (`tonemap.vert`), with an empty VAO bound.

## Known limitations and ideas

- Collider shapes: Box, Sphere, Capsule, Convex hull, Mesh, and None (child colliders only). Hull and Mesh are built from the entity's Mesh Renderer geometry (`Renderable::GetCollisionGeometry`; `Mesh` keeps a CPU copy). Mesh is static/kinematic only, since a dynamic one gets a hull. Compound bodies are made from child `ColliderComponent`s and are built when the body is created: moving or adding a part during Play does not rebuild the body, except through script `add_collider`. Raycasts and collision events report the body's entity, not the part. Triggers detect dynamic bodies only (not kinematic or static ones).
- Dialogue: no voice or portraits, no localization; the editor checks links but not Lua syntax (errors show at run time, in the Console); text fields don't word-wrap while typing (a wrapped preview shows below).
- UI layouts (UI Editor): no tabs widget or drag-and-drop between slots in layouts (use `ui.tabs` / `ui.slot` in code for those), no theme per layout (`ui.theme` applies), the preview only knows the preview values (not the live game).
- Laid-out UI: no keyboard or gamepad focus (number keys are up to the script), no text input field, no animation; auto-width panels don't wrap text and need sized bars; the font has Latin glyphs only (ImGui default ranges).
- Save games: no thumbnails, no versioning of scene files (a level file edited after a save still loads the save on top of the new file: changed entities win, new ones appear). Saving during combat is blocked by tactics.lua, not by the engine.
- Changing a RigidBody in the Inspector during Play applies on the next Play. Scripts rebuild a body with `add_body`.
- TAA: particles, glass and the sky carry only camera motion (no motion vectors of their own), so fast particles can trail briefly. Skinned limbs move with their entity only (the previous bone pose is not kept), and grass sway is not in its vectors: the neighbourhood clip hides most of this. A thin object moving fast close to the camera can look soft. There is no separate sharpening pass.
- Only the first sun and up to 4 point lights are used (`MaxLights`, `MAX_POINT_LIGHTS`).
- SSAO darkens direct light too (it multiplies the lit opaque colour), and its blur is not depth-aware.
- Skeletal animation: a base clip with a cross-fade or an animation graph (1D blends only: no 2D blend spaces or nested graphs; graph states and parameters are not saved in save games), override and additive layers, root motion and look/two-bone IK (no full-body IK; root motion takes only the base clip and ignores the clip fading out), at most 128 bones and 4 weights per vertex, skinned on the GPU every pass. Static models are flattened, so they have no node hierarchy.
- Transparency is sorted per entity (bounds centre), not per triangle: intersecting or concave see-through objects can show order errors. Back faces are culled unless the part is Double-sided, so a single-sided glass box shows only its front faces. Blended surfaces write no depth, so SSAO ignores them. They do write the entity ID, so clicking glass selects it.
- **Cascaded sun shadows** (`ShadowSettings`: `SunCascades`, `CascadeCount` 1-4, `ShadowDistance`, `CascadeSplit`). `GatherShadowViews` splits the camera view from its near plane to the shadow distance (a blend of even and logarithmic slices), fits each slice with a bounding sphere (its size depends only on the lens, so it is stable while the camera turns) and snaps it to whole texels (`FitSunView`), so shadows do not shimmer. The views, splits and count live in the `DrawList`, so the shadow pass and the lit pass use the same ones. The sun map is a 2D array texture, one layer per cascade (2048, at most 4). `lit.frag` picks the cascade by view depth (`u_ViewRow`, row 2 of the view matrix), blends over the last 10% of a cascade into the next, and fades out at the shadow distance. Bias is a few texels of each cascade (`SunBias` scales it; 0.002 is the default). With `SunCascades` off, one view covers `SunExtent` around the origin, as before. Viewport > Debug > Shadow Cascades tints them (not saved). Cascade splits are a `float[]` uniform: indexing a `vec4` with a loop variable read wrong values on this NVIDIA driver.
- Navigation: the grid is baked once (no partial re-bake), single-threaded, and only from static bodies (kinematic doors: block their cells instead). Units are not avoided outside of blocked cells, and slopes are walked as steps of one cell height (eased by the script).
- Terrain: no LOD (every chunk at full resolution), no per-layer normal maps, no holes, no runtime sculpting from scripts.
- Game database: one file per project; renaming an NPC id doesn't update scenes that use it; the database itself is read-only at run time (per-NPC state is in NpcComponent). The tactics hero is not an NPC (its gear is inventory.lua's `game.bag` / `game.equip`), and the goblins' attacks still do no damage.
- Candidate next steps: foot placement on uneven ground (limb IK driven by raycasts), blend trees, a Vulkan backend.
